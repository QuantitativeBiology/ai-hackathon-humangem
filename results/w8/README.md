## 1. What P1 is
**P1** (D11) = generic Human-GEM parent + W3 `B-loo:cofactor_pool_biomass` on the W2 documented medium M2(f=1), gate-free.
- The variant removes `MAM10012c` from `MAR13082`; the spec is in `results/w3/structure/variants_<parent>.json`.
- There is no context family, so nothing is pruned or repaired.
- P1(H1) is the selected pipeline. P1(H2) is its Human2 counterpart.

**Construction** (`resource.build_medium_variant_model`):
- `parent.copy()`, then `model.medium = bounds` (every other uptake is closed; secretion is unchanged);
- then `Variant.apply`, then objective `MAR13082`.
- These are the M6 sweep's steps, in the same order.

**Bounds.**
- They are rebuilt by W2's code and must hash to the W2 signature (asserted per model).
- Closed reactions are kept with bounds (0, 0): 8 per model, all from the parent.
- `version` is the Human-GEM release.

## 2. Storage scheme
**One gzipped SBML per (parent, medium signature), plus a line manifest.** P1 models differ across lines only by the medium signature.

| Path | Content |
|---|---|
| `resource/v1.0.0/medium-<sig>_<parent>-<ver>_P1.xml.gz` | 48 models, SBML L3V1 FBC v2, gzip with mtime 0, 1.75–2.14 MB each, **93.3 MB total** |
| `resource/models.tsv` | one row per model: sha256, size, counts, flags, the 5 DESIGN gates + `gate_reload_m6` (pass/FAIL), job status, CPU-s |
| `resource/manifest.tsv` | one row per (line, parent), 4,228 rows. Each row gives the model file and its sha256, plus the line's own metadata: medium key, documented text, source, **stratum = tier**, fallback flag, serum-free flag, documented serum %, lineage, `cancer` (DESIGN scope rule) and `screened` |
| `resource/README.md` | layout, line access, gate failures, licence (generated by the scripts) |

**Per-line SBML** (DESIGN naming `{ModelID}_{parent}-{version}_P1.xml.gz`):
- `scripts/w8_line_sbml.py --lines ACH-… --parent human2`, or `nextgem.resource.load_line("resource", ModelID, parent)`.
- Either one reads the shared file (sha256-checked) and adds the line's notes.

**Why not per-line files.**
- **Disk.** 4,228 × ≈ 1.9 MB ≈ 8.2 GB, close to the 10 GB cap on a 98%-full shared volume, as 88× duplicates of 48 models.
- **Compute.** Materialising measured 34 s per line, so ≈ 40 CPU-h in total.
- **Honesty about specificity.** PROMPT.md asks for "a resource of optimised, curated GEMs for DepMap 26Q3 cancer cell lines" and "generated context-specific models in SBML". P1's only line-specific input is the culture medium (no context family was selected, and W2-SHUF applies). Thousands of near-identical files would overstate the line specificity.
- **Every line still gets an SBML model:** its own manifest row, its own medium metadata and a sha-pinned file, with a per-line file one command away.

**SBML notes (every model).**
- `pipeline` (P1, D11), `pipeline_id`;
- `human_gem_release`, `parent_version`, `version`;
- `medium_signature`, `w2_sweep_id`, `medium_step`, `medium_keys`, `medium`;
- `medium_source_tier` / `line_strata` (tier counts of the lines sharing the file at build time);
- `serum`, `n_uptake_open`, `n_lines`;
- `w3_variant` (JSON);
- `git_commit`, `git_dirty`;
- `input_shas` (parent SBML, task file, variant spec, media library, floor tables, line assignment, reference sweeps, `Model.csv`);
- `flags`, `mevalonate_core_lethal`;
- `repaired_reactions` ("none …"), `licence`, `release_status`, `build_time_s`.

**Flags.**
- `W3-D1;W2-SHUF;W2-MOPEN` on all 48 models.
- `W3-MEV` on the 42 serum models. It is set from each model's own reference sweep (mevalonate core non-lethal).
- The 6 serum-free models (3 per parent) keep the core lethal and carry no W3-MEV.

### 4.1 The one gate failure: LP noise (documented; gate unchanged for v1.0.0 per PI)
**The failure.**
- Model: `medium-20cc933a4b852b6a_human2-2.1.1_P1` (RPMI + testosterone, 1 screened line).
- Gene: ENSG00000099817.
- The KO gives 0.0 in memory and −8.04e-9 after reload, which is above the 1e-9 absolute floor.

**Re-solve.** `scripts/w8_ko_noise_check.py` (212 CPU-s; `results/w8/ko_noise/`) re-solved the gate's own 20 genes on both models:

| Solver | ENSG00000099817 KO, in-memory model | ENSG00000099817 KO, reloaded model | Max \|Δ\| over 20 genes |
|---|---|---|---|
| GLPK, default tolerances | −1.5e-11 | −8.04e-9 (reproduced) | 8.0e-9 |
| GLPK, feasibility tolerance 1e-10 | 3.3e-13 | −2.5e-13 | 1.0e-12 |
| GLPK exact (rational arithmetic) | 0 | 0 | 0 |
| Gurobi, tolerances 1e-9 | 0 | 0 | 0 |

**Verdict.**
- The −8e-9 is a violation of the biomass lower bound (0) that is below GLPK's default primal feasibility tolerance (1e-7).
- The KO is exactly lethal, and the two models are equivalent.
- PI decision: the gate is unchanged for v1.0.0, and the miss stays documented as LP noise. Any change to the floor would be a post hoc rule for a future release.

**Exit code.**
- The committed build already returned 3 on any gate failure. The reported "exit 0" came from the invoking wrapper, not the script.
- The check is now explicit: `resource.gate_exit_code()` prints the failing models to stderr and returns 3. Tests: `test_w8_gate_exit_code` and `test_w8_build_main_propagates_exit_code`.
- Run on the final `models.tsv`, it returns 3 and lists this model.

## 6. Determinism
cobra keeps group members in a set, so identical models were written with a different member order and therefore different sha256 between runs.
- `write_sbml_gz` now sorts the members (`canonical_group_members`; test `test_w8_canonical_group_members`).
- The 40 screened-cohort files were built before this fix. They are content-identical to the fixed writer's output but not byte-reproducible.
- Files built after the fix are byte-stable.
